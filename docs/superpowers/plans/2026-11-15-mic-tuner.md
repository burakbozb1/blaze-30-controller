# Microphone Tuner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tuner screen that listens through the phone microphone and shows the nearest note, cents deviation and frequency.

**Architecture:** Pure-Kotlin core in a new `tuner/` package (`NoteMath`, `PitchDetector` with YIN, `TunerController` fed by an `AudioSource` interface), an `AudioRecord`-backed `MicAudioSource`, and a Compose `TunerScreen` reached from the home screen. Independent of the Bluetooth/amp code.

**Tech Stack:** Kotlin, coroutines/Flow, Jetpack Compose, `android.media.AudioRecord`, JUnit4 + kotlinx-coroutines-test (existing project).

**Spec:** `docs/superpowers/specs/2026-11-15-mic-tuner-design.md`

**Build note:** run Gradle through the `X:` drive (`subst X: "<project dir>"`; `./gradlew.bat --no-daemon ...`); phone adb is over wireless debugging.

## Global Constraints

- Manifest permissions become exactly `BLUETOOTH_SCAN` (neverForLocation), `BLUETOOTH_CONNECT`, `RECORD_AUDIO`. No INTERNET, nothing else.
- Audio is never stored, logged or sent anywhere; no raw samples in logs.
- Capture format: 44 100 Hz, mono, PCM 16-bit, frames of 4096 samples. Reference A4 = 440 Hz fixed. Detection range 55–1100 Hz.
- Microphone is open only while the Tuner screen is visible and the activity is STARTED.
- Out of scope: transposition, A4 setting, tuning presets, amp interaction.

## Review Focus

1. Silence, room noise, mains hum → "no signal", never a random note (Task 2 and Task 3 tests).
2. Low E with a strong 2nd harmonic / weak fundamental → correct octave within 2 cents (Task 2).
3. Microphone unavailable/busy or permission revoked mid-session → error state with a message, no crash; reopening the screen recovers (Tasks 3, 5).
4. Leaving the screen or backgrounding the app releases `AudioRecord` (no leaked microphone) (Task 3 unit test with a counting fake; Task 5 device check).
5. A single glitch frame (octave jump, clipping) must not flash a wrong note (Task 3 median test).

### Task 2: Pitch detector (YIN)

**Files:**
- Create: `app/src/main/java/dev/blaze/controller/tuner/PitchDetector.kt`
- Test: `app/src/test/java/dev/blaze/controller/tuner/PitchDetectorTest.kt` (with a small synthetic-signal helper in the test)

**Interfaces — Produces:**
```kotlin
class PitchDetector(
    val sampleRate: Int = 44_100, val minHz: Double = 55.0, val maxHz: Double = 1_100.0,
    val threshold: Double = 0.15, val minRms: Double = 0.01,
) { fun detect(samples: ShortArray): Double? }   // fundamental in Hz, or null if no clear pitch
```
Algorithm: reject if RMS (of samples/32768) < `minRms`; YIN difference + cumulative-mean-normalised difference over τ ≤ sampleRate/minHz on a half-window; first τ below `threshold` then walk to the local minimum; parabolic interpolation; frequency outside [minHz, maxHz] → `null`.

- [ ] **Step 1: Write failing tests** (4096-sample frames, 44 100 Hz, amplitude 0.3 of full scale unless noted):
  - `detectsEachStandardStringWithinOneCent`: pure sines at 82.41, 110.0, 146.83, 196.0, 246.94, 329.63 → result within ±1 cent of the input.
  - `detectsDetunedLowE`: 82.41·2^(±40/1200) → within ±1.5 cents.
  - `lowEWithStrongSecondHarmonicStillGivesTheFundamental`: harmonics amplitudes 0.15 / 0.45 / 0.25 / 0.1 on 82.41 → within 2 cents of 82.41 (not 164.8).
  - `guitarLikeSawtoothOnA2`: partials 1..8 with 1/n amplitudes at 110 Hz → within 2 cents.
  - `silenceReturnsNull`, `veryQuietSignalReturnsNull` (amplitude 0.002), `whiteNoiseReturnsNull` (seeded `java.util.Random(1)`, amplitude 0.3), `mainsHum50HzReturnsNull` (50 Hz sine is below `minHz`), `ultrasonicToneReturnsNull` (3000 Hz).
  - `clippedLoudSineStillDetects`: 110 Hz sine amplitude 1.5 clipped to ±32767 → within 3 cents.

### Task 3: Tuner controller

**Files:**
- Create: `app/src/main/java/dev/blaze/controller/tuner/TunerController.kt`
- Test: `app/src/test/java/dev/blaze/controller/tuner/TunerControllerTest.kt`

**Interfaces — Consumes:** `PitchDetector.detect`, `NoteMath.fromFrequency`. **Produces:**
```kotlin
interface AudioSource { fun frames(): Flow<ShortArray> }  // 4096-sample frames; throws IllegalStateException when the microphone cannot be opened
sealed interface TunerUi { data object NoSignal : TunerUi; data class Reading(val note: NoteReading) : TunerUi; data class Error(val message: String) : TunerUi }
class TunerController(source: AudioSource, detector: PitchDetector = PitchDetector(), holdFrames: Int = 5, medianSize: Int = 5) {
    val ui: StateFlow<TunerUi>            // starts as NoSignal
    suspend fun run()                     // collects source.frames() until cancelled; never throws except CancellationException
}
```
Behavior: per frame detect; keep the last `medianSize` detected frequencies and show the median (by log-frequency); after `holdFrames` consecutive frames without a pitch show `NoSignal`; an exception from the source → `Error("Mikrofon kullanılamıyor")`; cancellation releases the source (the flow's own `finally`).

- [ ] **Step 1: Write failing tests** with a fake `AudioSource` (a `flow { frames.forEach { emit(it) } }` that counts starts/finishes) and synthetic frames:
  - `steadyLowEShowsE2OnString6`: 8 frames of 82.41 Hz → `Reading` with `name == "E"`, `octave == 2`, `|cents| < 2`, `string == 6`.
  - `silenceShowsNoSignalAndNeverANote`: 20 frames of silence and 20 frames of seeded noise → `NoSignal` throughout (Review Focus 1).
  - `holdsTheLastNoteBrieflyThenGoesToNoSignal`: 5 E2 frames, then 4 silent frames → still `Reading`; after the 5th silent frame → `NoSignal`.
  - `aSingleOctaveGlitchFrameDoesNotFlipTheDisplay`: E2 ×4, one 164.82 Hz frame, E2 ×2 → the displayed note stays E2 at every step after the first 3 frames (Review Focus 5).
  - `sourceFailureShowsAnErrorAndDoesNotCrash`: source throws `IllegalStateException` → `Error`; `run()` returns normally (Review Focus 3).
  - `cancellingRunReleasesTheSource`: source records when its flow completes/cancels; after `job.cancel()` the count of releases equals the count of starts (Review Focus 4).
